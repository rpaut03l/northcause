OVERVIEW

NorthCause turns operational evidence into reviewable investigations.

Connect OpenTelemetry traces, signed GitHub deployment events, RAG evaluations, GPU or Kubernetes events, and CI/CD output. NorthCause organizes the signals for investigation while keeping evidence and decision boundaries visible.

Evidence before confidence

Findings include references to source evidence. When the available material does not support an explanation, the result is marked as insufficient evidence.

Investigation workflow

  1. Connect traces. Send bounded OTLP JSON spans with service and deployment metadata.
  2. Connect GitHub. Configure a signed webhook for pushes and deployment status updates.
  3. Evaluate changes. Use paired exact-match replay or the optional customer-configured semantic judge.
  4. Review a draft. A human approves or rejects remediation guidance with a reason. No production change is applied by this pilot.
  5. Verify and export. Each paired replay creates an Ed25519-signed proof record with a verifiable hash-chain link.

Evidence formats and handling

Text evidence can include .log, .txt, .json, .ndjson, .csv, and .yaml. File size and per-incident limits are enforced. Some common secret-like patterns are redacted before evidence is stored; uploads are size-limited and fingerprinted. Pattern-based redaction can miss sensitive values.

OTLP ingestion stores trace and span identifiers, service/environment labels, timing, status, and a narrow allowlist of attributes. Prompt, completion, request/response body, and content attributes are discarded. Configure collector-side filtering too.

Security and model use

The deterministic analyzer does not send evidence to a model. Semantic judging is disabled until an administrator configures a customer-controlled OpenAI-compatible endpoint and API key. Evaluation text is sent to that endpoint for scoring and is not persisted by NorthCause; the endpoint provider may have its own retention terms.

Remediation remains draft-only and requires a human decision. The SOS endpoint creates an incident record; it does not page staff, provide a response SLA, or perform automatic containment.

Integrations

Configure NORTHCAUSE_OTEL_INGEST_TOKEN for POST /api/otel/v1/traces and NORTHCAUSE_GITHUB_WEBHOOK_SECRET for POST /api/integrations/github/webhook. Payload sizes are bounded and GitHub HMAC signatures are checked. Setup instructions and environment variables are in the integration guide.

API reference

  • POST /api/otel/v1/traces - authenticated OTLP JSON intake.
  • POST /api/integrations/github/webhook - signed GitHub push/deployment events.
  • POST /api/evaluations/semantic - session-authenticated semantic evaluation.
  • POST /api/sos - authenticated SOS intake that creates a high-severity incident.
  • GET /api/proofs/{id} - authenticated signed proof export.
  • GET /api/proofs/{id}/verify - public signature and payload verification.
